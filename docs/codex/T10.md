# CODEX TASK T10: Пакет для семейного пилота

**Статус: задание для последовательной реализации в подключённом репозитории GitHub; сначала выполнить зависимости.**

## Context

«Наши истории»: согласованный MVP — веб-игра для мамы и дочки на одном Android-телефоне в Chrome. 60 неизменённых вопросов Excel, 6 тем по 10, глубины 21/25/14. Ручной выбор или две рулетки (1/6 и 1/3, включая исчерпанные), отдельное подтверждение. Вопрос равновероятен среди непоказанных сочетания. Мини-раунд без фиксированной длины; обе могут отвечать или пропустить. Нет повторов внутри игры, даже после смены выбора. Восстановление на устройстве и автономность после первой загрузки. Без аккаунтов, редактора, ответов, аудио, аналитики и сервера пользовательских данных.

Состояние на входе: T09: предварительная техническая готовность; T00: доступ к GitHub и выбранная видимость репозитория; без покупки платных услуг. Фактическую реализацию зависимостей проверить в репозитории и отчётах; само наличие этого файла не доказывает их готовность. При подготовке документации v1.0 приложение ещё не реализовано; актуальное состояние проверить в репозитории.

## Objective

Опубликовать проверенную сборку через GitHub Actions на Pages и подготовить понятные инструкции семейного теста.

## Relevant requirements

PRD пилот; TECH_SPEC §16/20/21; ROADMAP этап 7; TEST_PLAN T-17/18. Основные документы: docs/DECISIONS.md, docs/TECH_SPEC.md, docs/DATA_MODEL.md, docs/UX_FLOWS.md, docs/ARCHITECTURE.md и docs/TEST_PLAN.md.

## Implementation requirements

Подготовить production dist, номер выпуска, контроль состава/размера и короткую русскую инструкцию: открыть онлайн, дождаться готовности, выбрать тему/глубину, крутить или выбрать вручную, подтвердить, пропустить/сменить, продолжить после возврата. Объяснить локальное хранение и очистку данных. Документировать развёртывание, обратимый возврат к прошлой сборке с совместимостью кеша, и проверку HTTPS/base path. Публикация самой игры из main через GitHub Actions на Pages прямо разрешена пользователем. Проверить Source=GitHub Actions, workflow, main и права Pages; после прохождения проверок проследить run до завершения, открыть итоговый HTTPS URL, проверить ресурсы/PWA в подпапке. Не выбирать платный тариф, не создавать аккаунты и не менять видимость исходного репозитория автоматически. Если административные возможности недоступны — подготовить всё остальное и точно назвать оставшийся шаг. Не выдавать шаблон workflow за фактический успешный deploy. Подготовить пустую форму добровольного отзыва, не собирать рассказы и не отправлять сообщения участницам.

Сначала проверить зависимости задачи; не принимать наличие документа за выполненную реализацию.
- Сначала изучить репозиторий и связанные инструкции, включая все применимые AGENTS.md; использовать существующую структуру и команды.
- Не переписывать работающий код без необходимости, не удалять существующую функциональность, не создавать проект заново.
- Не добавлять функции за пределами этой задачи и не менять тексты, темы и глубины колоды.
- Не устанавливать новые зависимости без обоснования, соблюдать соглашения проекта.
- Не изменять конфиденциальные файлы и секреты, не выводить их в отчёт и не включать в браузерную сборку.
- Не выполнять опасные необратимые операции без подтверждения. Автоматическая публикация приложения из main на GitHub Pages разрешена пользователем; не публиковать личные исходные заметки и не менять доступ к исходному репозиторию без решения о его видимости.
- Создавать или обновлять содержательные тесты. Не объявлять задачу завершённой, если обязательные проверки не пройдены; недоступные проверки назвать явно.
