# CODEX TASK T00: Отдельный GitHub-репозиторий и подключение Codex

## Context

«Наши истории» — семейная веб-игра для мамы и дочки на одном Android-телефоне с Chrome. MVP: 60 неизменённых вопросов Excel, 6 тем по 10, глубины 21/25/14; ручной выбор/две равновероятные рулетки с подтверждением, свободные мини-раунды без повторов, пропуск, восстановление и PWA-офлайн. Без серверной БД, аккаунтов и аудио.

Пользователь поручил создать отдельный GitHub-репозиторий, разрабатывать через его подключение к Codex и автоматически публиковать main через GitHub Actions на Pages. Нужен существующий Node.js LTS >=22, совместимый с Vite. Обычная HTTPS-ссылка без пароля достаточна. Документация подготовлена, приложение и репозиторий пока не созданы.

## Objective

Создать или проверить отдельный репозиторий игры и обеспечить доступ Codex для последовательного выполнения T01…T10.

## Relevant requirements

FR-20/21, Р-20…Р-25; docs/DEPLOYMENT.md, docs/DECISIONS.md, AGENTS.md. Эта задача не реализует саму игру.

## Repository inspection

Сначала изучить применимые AGENTS.md, текущую папку и подключённые репозитории GitHub. Проверить, не создан ли уже nashi-istorii в аккаунте пользователя. Использовать существующий подходящий репозиторий только если он действительно относится к этой игре; не заменять им чужой проект. Проверить статус доступа, main и origin.

## Implementation requirements

Предлагаемое имя nashi-istorii. Если пользователь уже создал репозиторий, проверить точную ссылку и подключение. Иначе использовать имеющиеся операции GitHub для создания. Видимость исходников и тариф не считать вытекающими из обычной ссылки на игру: на GitHub Free Pages требует публичный repo, приватный зависит от плана. Не менять видимость и не покупать тариф автоматически.

Доступ Codex должен охватывать новый репозиторий. Не запрашивать токены в чате и не создавать новые ключи. Если операция требует действий пользователя в настройках подключения, сообщить конкретный шаг. После доступа подготовить отдельный checkout; не превращать родительскую папку книг в репозиторий игры.

Переносить документацию и действующую колоду выборочно. Перед публичным commit исключить личные контекстные TXT и manifest с абсолютными пользовательскими путями; подготовить источник с относительным путём/хешем. Не загружать весь локальный архив вслепую. GitHub Actions начнёт полноценно работать после T01 и последующих реализаций.

## Constraints

- Сначала изучить структуру репозитория и AGENTS.md, соблюдать соглашения.
- Не переписывать работающий код и не удалять существующие функции.
- Не добавлять функций за рамками задачи; не устанавливать зависимости без обоснования.
- Не изменять секреты и конфиденциальные файлы, не выводить токены или ключи.
- Не выполнять опасные необратимые операции без подтверждения.
- Публикация самой игры из main на Pages разрешена; это не разрешает публикацию личных заметок или платный тариф.
- Не обходить ограничения подключения; не выдавать локальную папку за созданный GitHub-репозиторий.
- Создавать/обновлять тесты там, где появляется проверяемая логика; эта задача проверяется чтением фактических метаданных GitHub, а не искусственным тестом имени папки.
- Не объявлять задачу завершённой, если проверки не пройдены. Все предположения и отклонения от ТЗ явно отметить.

## Files and modules

Метаданные репозитория, main, origin, выбранный checkout, README и безопасный состав документов. Не создавать приложение в этой задаче.

## Edge cases

Репозиторий уже существует; нет прав создания; новый repo не разрешён GitHub-подключению; нет main; private repo не поддерживает Pages на текущем плане; браузер требует входа; инструменты не позволяют настроить Pages.

## Tests

Проверить существование точного owner/repo, доступ через подключение Codex, главную ветку и origin. До первого commit проверить перечень переносимых файлов на личные заметки/секреты. Приложения ещё нет — не утверждать, что его тесты пройдены.

## Verification

Считать фактические метаданные репозитория и список файлов/веток через GitHub-коннектор или авторизованный CLI. При невозможности создания дать конкретную ссылку на создание и минимальную инструкцию подключения; остальную подготовку завершить.

## Acceptance criteria

Репозиторий реально существует, точная ссылка известна, main и доступ Codex проверены; подготовлен отдельный checkout или описан конкретный оставшийся шаг. При отсутствии создания/доступа задача остаётся невыполненной. Платные услуги не подключены, личные заметки не опубликованы.

## Final report

- Что создано/подключено и ссылка на owner/repo.
- Какие файлы перенесены и почему.
- Какие проверки выполнены и результаты.
- Что не удалось проверить и какие действия пользователя необходимы.
- Ограничения, предположения и отклонения.
