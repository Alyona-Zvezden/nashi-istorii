# CODEX TASK T06: Сохранение и восстановление одной игры

**Статус: задание для последовательной реализации в подключённом репозитории GitHub; сначала выполнить зависимости.**

## Context

«Наши истории»: согласованный MVP — веб-игра для мамы и дочки на одном Android-телефоне в Chrome. 60 неизменённых вопросов Excel, 6 тем по 10, глубины 21/25/14. Ручной выбор или две рулетки (1/6 и 1/3, включая исчерпанные), отдельное подтверждение. Вопрос равновероятен среди непоказанных сочетания. Мини-раунд без фиксированной длины; обе могут отвечать или пропустить. Нет повторов внутри игры, даже после смены выбора. Восстановление на устройстве и автономность после первой загрузки. Без аккаунтов, редактора, ответов, аудио, аналитики и сервера пользовательских данных.

Состояние на входе: T05. Фактическую реализацию зависимостей проверить в репозитории и отчётах; само наличие этого файла не доказывает их готовность. При подготовке документации v1.0 приложение ещё не реализовано; актуальное состояние проверить в репозитории.

## Objective

Заменить временное хранение на валидируемый локальный снимок с восстановлением.

Действующая колода — sources/Наши_истории_60_вопросов_редакция.xlsx.

## Implementation requirements

Реализовать утверждённую схему IndexedDB, store session и стабильный meta.activeRelease, read/save/clear с раздельными результатами. Снимок с buildId и привязку к выпуску записывать одной транзакцией; revision читать и сравнивать в этой же транзакции. Принимать переход только после transaction complete, не отдельного put. При ошибке оставить прежний принятый экран и тот же кандидат для retry. При запуске валидный снимок ведёт к «Продолжить/Начать новую»; продолжение не вызывает случайность. Сохранять выбор до анимации; при возврате показывать готовый результат. Завершение/сброс удаляют snapshot и activeRelease одной транзакцией после подтверждения. Повреждённый/несовместимый снимок не удалять автоматически. При несовпадении revision не перезаписывать состояние; при возврате фокуса перечитывать revision. Поддерживаемый режим — одна активная вкладка, без объединения состояний.
