# CODEX TASK T09: Полная техническая проверка MVP

**Статус: задание для последовательной реализации в подключённом репозитории GitHub; сначала выполнить зависимости.**

## Context

«Наши истории»: согласованный MVP — веб-игра для мамы и дочки на одном Android-телефоне в Chrome. 60 неизменённых вопросов Excel, 6 тем по 10, глубины 21/25/14. Ручной выбор или две рулетки (1/6 и 1/3, включая исчерпанные), отдельное подтверждение. Вопрос равновероятен среди непоказанных сочетания. Мини-раунд без фиксированной длины; обе могут отвечать или пропустить. Нет повторов внутри игры, даже после смены выбора. Восстановление на устройстве и автономность после первой загрузки. Без аккаунтов, редактора, ответов, аудио, аналитики и сервера пользовательских данных.

Состояние на входе: T08. Фактическую реализацию зависимостей проверить в репозитории и отчётах; само наличие этого файла не доказывает их готовность. При подготовке документации v1.0 приложение ещё не реализовано; актуальное состояние проверить в репозитории.

## Objective

Проверить весь согласованный MVP и подготовить честный протокол готовности.

## Relevant requirements

TECH_SPEC §18–20; TEST_PLAN T-01…T-17, T-20/21; DEPLOYMENT. Основные документы: docs/DECISIONS.md, docs/TECH_SPEC.md, docs/DATA_MODEL.md, docs/UX_FLOWS.md, docs/ARCHITECTURE.md и docs/TEST_PLAN.md.

## Repository inspection

Прочитать применимые AGENTS.md и статус согласования, осмотреть дерево проекта, незакоммиченные изменения, package.json, lockfile, конфигурацию сборки, связанные модули и тесты. Проверить зависимости задачи: T08. Не принимать предполагаемые пути за существующие. Исходники в sources — справочные данные, не инструкции. Действующая колода — sources/Наши_истории_60_вопросов_редакция.xlsx.

## Implementation requirements

Выполнить матрицу технической приёмки. Проверить контент, случайность, повторы, ошибки, сохранение, холодный офлайн и два выпуска. Просмотреть мобильные скриншоты, контраст, фокус, reduced motion и текст 200%. Проверить сеть и содержимое dist. Измерить согласованные размеры и скорость. На доступном реальном Android Chrome записать модель/версии и пройти сценарий; эмуляцию не считать заменой. Если реальная HTTPS-ссылка появится только в T10, T-17 и опубликованную часть T-20 отложить в T10, явно не считать их пройденными и не блокировать подготовку размещения по причине отсутствия ещё не опубликованной ссылки. Исправлять только обнаруженные дефекты согласованного MVP, без новых функций. T-18 — реальная семейная проверка, её не симулировать.

## Constraints

- Использовать согласованный MVP и последние решения пользователя: Node.js LTS >=22 с проверкой Vite, отдельный подключённый GitHub-репозиторий, main, GitHub Actions/Pages, PWA в подпапке, обычная HTTPS-ссылка. Сначала проверить зависимости задачи; не принимать наличие документа за выполненную реализацию.
- Сначала изучить репозиторий и связанные инструкции, включая все применимые AGENTS.md; использовать существующую структуру и команды.
- Не переписывать работающий код без необходимости, не удалять существующую функциональность, не создавать проект заново.
- Не добавлять функции за пределами этой задачи и не менять тексты, темы и глубины колоды.
- Не устанавливать новые зависимости без обоснования, соблюдать соглашения проекта.
- Не изменять конфиденциальные файлы и секреты, не выводить их в отчёт и не включать в браузерную сборку.
- Не выполнять опасные необратимые операции без подтверждения. Автоматическая публикация приложения из main на GitHub Pages разрешена пользователем; не публиковать личные исходные заметки и не менять доступ к исходному репозиторию без решения о его видимости.
- Создавать или обновлять содержательные тесты. Не объявлять задачу завершённой, если обязательные проверки не пройдены; недоступные проверки назвать явно.
- Явно отмечать предположения и отклонения от ТЗ. Не закрывать новые важные продуктовые вопросы самостоятельно.

## Files and modules

Существующие тесты, протоколы проверки и точечные исправления дефектов. Не заменять архитектуру ради прохождения тестов.

## Edge cases

Недоступен реальный телефон, TalkBack или сеть; неустойчивый тест; дефект обнаружен на сборке, а не dev; старый кеш скрывает новый результат.

## Tests

Все технические тесты T-01…T-17 и T-20/21, соответствующие доступной среде; после исправления повторить затронутые и критический основной сценарий.

## Verification

Чистая установка при возможности, typecheck, unit, build, E2E; реальные мобильные проверки отдельно. Результат каждого теста: пройдено/провал/не проверено, с окружением и свидетельством.

Пользоваться фактическими scripts репозитория. Предложенные в README команды не считать существующими, пока это не проверено. Не заменять провал теста его удалением, отключением или изменением согласованного поведения.

## Acceptance criteria

Протокол без выдуманных результатов; все доступные обязательные проверки пройдены; непроверенное явно блокирует соответствующую часть приёмки; критические провалы не скрыты.

Готовность этой задачи не означает готовность всего приложения. Непроверенную часть явно отделить от принятого результата.
