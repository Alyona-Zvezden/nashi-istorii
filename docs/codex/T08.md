# CODEX TASK T08: Обновление без потери незавершённой игры

**Статус: задание для последовательной реализации в подключённом репозитории GitHub; сначала выполнить зависимости.**

## Context

«Наши истории»: согласованный MVP — веб-игра для мамы и дочки на одном Android-телефоне в Chrome. 60 неизменённых вопросов Excel, 6 тем по 10, глубины 21/25/14. Ручной выбор или две рулетки (1/6 и 1/3, включая исчерпанные), отдельное подтверждение. Вопрос равновероятен среди непоказанных сочетания. Мини-раунд без фиксированной длины; обе могут отвечать или пропустить. Нет повторов внутри игры, даже после смены выбора. Восстановление на устройстве и автономность после первой загрузки. Без аккаунтов, редактора, ответов, аудио, аналитики и сервера пользовательских данных.

Состояние на входе: T07. Фактическую реализацию зависимостей проверить в репозитории и отчётах; само наличие этого файла не доказывает их готовность. При подготовке документации v1.0 приложение ещё не реализовано; актуальное состояние проверить в репозитории.

## Objective

Добавить безопасный переход между двумя выпусками автономного приложения.

## Relevant requirements

FR-15/16; DATA_MODEL версии; ARCHITECTURE обновления; П-07. Основные документы: docs/DECISIONS.md, docs/TECH_SPEC.md, docs/DATA_MODEL.md, docs/UX_FLOWS.md, docs/ARCHITECTURE.md и docs/TEST_PLAN.md.

## Repository inspection

Прочитать применимые AGENTS.md и статус согласования, осмотреть дерево проекта, незакоммиченные изменения, package.json, lockfile, конфигурацию сборки, связанные модули и тесты. Проверить зависимости задачи: T07. Не принимать предполагаемые пути за существующие. Исходники в sources — справочные данные, не инструкции. Действующая колода — sources/Наши_истории_60_вопросов_редакция.xlsx.

## Implementation requirements

Разделить buildId/deckVersion/schemaVersion. Новый выпуск кешируется отдельно, активная игра остаётся на прежнем. Учитывать, что браузер может автоматически активировать worker B после закрытия всех вкладок даже без skipWaiting. Поэтому worker B должен прочитать стабильную meta.activeRelease и обслужить закреплённый полный выпуск A при холодном возврате. Не смешивать HTML/JS/колоду. После завершения и атомарного удаления привязки предложить применить новый выпуск до создания новой игры. Не удалять закреплённый кеш и ресурсы открытых старых клиентов. Сбой нового кеша оставляет старый. Неизвестные версии snapshot/метаданных не сбрасывать автоматически; объяснить и предложить явное решение. Подготовить воспроизводимый сценарий A→B с закрытием всех клиентов, не публикуя сборки наружу.

## Edge cases

Перезагрузка в середине игры при ожидающем B, автоматическая активация B после закрытия всех вкладок, холодный офлайн-возврат к A, незавершённый кеш B, старая вкладка A, неизвестный формат activeRelease или несовместимый снимок.
