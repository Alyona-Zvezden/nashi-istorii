# План тестирования и приёмки

Редакция v1.0 · **Требования и техническая детализация.** Это план будущих проверок, не отчёт об их прохождении. Проверка документации при подготовке не равна проверке приложения. Сейчас кода нет.

## Среды и правила

Чистые проверки: Vitest, источник случайности подменяется. Браузерные: Playwright Chromium на production build, не только dev server. Ручные: реальный Android Chrome телефона семьи, записать модель, Android/Chrome, адрес и buildId. Значения технических порогов — П-06.

Для тестирования использовать только колоду и искусственные снимки, без ответов и персональных данных. Каждый E2E начинает с изолированного browser context. Изменение времени/сети/хранилища должно быть явным и возвращаться к исходным условиям. Обновление проверять двумя различными сборками и отдельными кешами.

## Последовательность

1. T-01/02 и инварианты T-05/06 проходят до подключения UI.
2. T-03…T-10 проверяются по мере появления экранов и хранения.
3. T-11…T-14 — на полной сборке, с реальным service worker и двумя выпусками для обновления.
4. T-15/16 — на финальной сборке; T-19/20 — при публикации. T-17 — на реальном телефоне по опубликованной HTTPS-ссылке, после автоматических проверок. До публикации предварительная приёмка может быть завершена с явно отложенными реальными проверками.
5. T-18 — семейный пилот после технической готовности; его нельзя выполнить вместо участниц.
6. T-21 выполняется в начале T01 и повторяется в CI; до установки Vite одна лишь версия Node не считается достаточным доказательством совместимости.

## Формат протокола

Для каждого теста: дата, test ID, commit/buildId, deckVersion, устройство/ОС/браузер, действия, ожидание, фактический результат, статус «пройдено / провал / не проверено», ссылка на артефакт/лог без чувствительных данных, дефект и повторная проверка при исправлении. Скриншоты не должны содержать ответы семьи.

Критичны: несовпадение контента, повтор ID внутри игры, потеря подтверждённого состояния, отсутствие автономного холодного запуска, обход подтверждения рулетки, непрошедшие обязательные проверки. Не объявлять выпуск принятым с критическим провалом. Недоступный реальный телефон означает незавершённую мобильную приёмку, а не успешную эмуляцию.
