# Модель данных и хранение

Редакция v1.0 · **Требования и техническая детализация.** Внутренние решения — П-02/03/04/07. Состояние содержит только игру, без ответов и сведений об участницах; серверной БД нет.

| Сущность/поле | Тип и смысл | Ограничение |

| Deck.deckVersion | Строка версии контента, первоначально `base-60-v1` | Изменяется при изменении контента/соответствия ID |

## Снимок активной игры — П-02

База IndexedDB: `nashi-istorii:<repository>`, начальная версия БД 1. Repository slug берётся из той же конфигурации, что BASE_PATH; для предлагаемого имени — nashi-istorii:nashi-istorii. Это исключает пересечение с другими project sites того же owner на общем origin. Store session содержит одну запись с ключом active; store meta — стабильную запись activeRelease. Снимок заменяется целиком, без записей на каждую карточку. Снимок и activeRelease создаются/обновляются/удаляются одной readwrite-транзакцией. Истории завершённых встреч нет. Схема снимка:

| Поле | Тип | Смысл |
|---|---|---|
| schemaVersion | Целое, первоначально 1 | Версия структуры снимка |
| deckVersion | Строка | Используемая версия колоды |
| buildId | Строка | Закреплённый полный выпуск ресурсов для этой игры |
| sessionId | Строка UUID | Идентификатор игры, без связи с человеком |
| revision | Неотрицательное целое | Увеличивается при принятом изменении |
| startedAt, updatedAt | ISO-строки UTC | Техническое время; не участвует в игровой случайности |
| phase | theme / depth / question / exhausted | Экран, на который продолжится игра |
| themeId | Theme ID или null | Выбранная тема |
| depth | 1/2/3 или null | Выбранная глубина |
| currentQuestionId | Question ID или null | Текущая показанная карточка |
| shownIds | Массив уникальных Question ID | Все когда-либо показанные в этой игре |

Промежуточные выборы темы/глубины сохраняются, но сами по себе не добавляют shownIds. Вращение не хранится как длительный процесс: результат определяется и сохраняется до анимации; после перезагрузки виден готовый выбор без нового броска. Правила и диалоги подтверждения — временные UI-состояния, в снимок не записываются.

## Инварианты

1. shownIds уникальны, принадлежат deckVersion, размер 0…60. Смена темы/глубины их не уменьшает.
2. phase=theme: themeId может быть null/выбранным, depth=null, currentQuestionId=null. Показанные сохраняются.
3. phase=depth: themeId обязателен; depth может быть null/выбранным; currentQuestionId=null.
4. phase=question: themeId/depth обязательны; currentQuestionId существует, относится к выбору и включён в shownIds.
5. phase=exhausted: themeId/depth обязательны; currentQuestionId=null; нет доступных карточек данного сочетания.
6. Состояние question с последней доступной карточкой допустимо: карточка уже в shownIds, но остаётся на экране до следующего действия.
7. Только новая игра создаёт пустую историю. Подтверждённое завершение удаляет снимок и привязку к выпуску одной транзакцией. Ни то ни другое не выполняется автоматически при исчерпании или ошибке.
8. Неизвестная schemaVersion/deckVersion, дубли ID, некорректные комбинации phase/полей и повреждённая запись считаются ошибкой, не частично исправляются молча.
9. meta.activeRelease имеет стабильные поля formatVersion=1, sessionId и buildId; sessionId/buildId совпадают со снимком. Эта запись нужна worker для выбора выпуска до появления страницы. Не менять её формат без обратной совместимости.

## Порядок переходов — П-03/04

1. Получить действие UI и проверить, что переход разрешён; заблокировать повторную активацию действия.
2. Сформировать один кандидат нового состояния из последнего принятого. Для выдачи карточки случайный выбор выполнить один раз.
3. Провалидировать кандидат, в одной транзакции проверить актуальную revision и записать снимок с activeRelease. Только после события завершения всей транзакции (не отдельного put) принять его в памяти и показать новый экран.
4. Если запись не удалась, предыдущий принятый экран остаётся; кандидат удерживается для «Повторить», а не перевыбирается.
5. После перезагрузки при сбое виден последний успешно сохранённый снимок. Это не гарантирует сохранение незавершённого нажатия.

Момент показа карточки: успешная фиксация снимка перед визуальным выводом. Если браузер закрыт между фиксацией и выводом, продолжение показывает эту же карточку. Она не теряется и не выбирается второй раз.

«Сменить тему или глубину» сохраняет phase=theme, предварительно выбранную прежнюю тему, depth=null, currentQuestionId=null и прежние shownIds. Для смены только глубины достаточно подтвердить прежнюю тему. «Назад» из depth аналогично ведёт к theme и сбрасывает глубину, не расходуя вопрос.

## Ошибки и несколько вкладок

Открытие БД, чтение, запись и завершение транзакции могут завершиться ошибкой. Сначала проверить доступность. Не переключаться автоматически на несохраняемый режим: он нарушает ожидания восстановления. Предложить повтор, объяснив проблему. Самостоятельно очищать все данные origin запрещено. События blocked/versionchange не должны зависнуть навсегда: объяснить необходимость закрыть другую вкладку, не теряя принятый снимок.

Чтение ожидаемых sessionId/revision и запись кандидата выполняются в одной readwrite-транзакции по обоим stores. При несовпадении прервать переход и предложить загрузить актуальную сохранённую игру. При возврате фокуса перечитывать revision, но именно транзакция защищает от перезаписи между проверкой и записью. Поддерживаемый сценарий — одна активная вкладка; сетевую синхронизацию и объединение состояний не добавлять. Отдельно проверить последовательные и почти одновременные изменения в двух вкладках.

## Выпуски и удаление

buildId — версия полного набора HTML/JS/CSS/колоды в кеше. deckVersion — версия вопросов; schemaVersion — структура сохранения. Их нельзя подменять друг другом.

Пока есть активная игра, новый service worker обслуживает закреплённый buildId, даже если браузер активировал worker после закрытия всех вкладок. Для выбора HTML worker читает стабильную meta.activeRelease, а не пытается читать localStorage или интерпретировать неизвестную игровую схему. Нельзя удалять закреплённый кеш при activate. После завершения игры предложить применить доступный выпуск до создания следующей. Совместимость новой схемы проверяется заранее; миграции не удаляют рабочие записи. При несовместимости предложить старый выпуск, если доступен, или явный сброс после объяснения.

После подтверждённого завершения удаляются только snapshot и meta.activeRelease в одной транзакции; UI меняется после её завершения. Кеш приложения остаётся для офлайна. При сбросе повреждённого снимка удаляются только эти связанные записи после подтверждения. Экспорт/импорт истории и облачное резервирование в MVP не предусмотрены.

Очистка данных сайта, смена адреса сайта, другой профиль, приватный режим и очистка браузером ограничивают восстановление. Это допустимые ограничения веб-хранения, которые нужно объяснить в правилах. Истории и ответы не сохраняются.
