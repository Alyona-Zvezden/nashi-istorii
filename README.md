# Сближение

Семейная игра для живого разговора. Одна колода из 60 вопросов, шесть тем, три уровня глубины и две рулетки. Один общий телефон; без аккаунтов, записи ответов и серверной базы данных.

[Открыть игру](https://alyona-zvezden.github.io/nashi-istorii/)

## Как играть

1. Выберите тему вручную или нажмите «Крутить», затем «Продолжить».
2. Выберите глубину разговора — сами или рулеткой — и подтвердите.
3. На вопрос могут ответить все желающие, в свободном порядке. Можно ответить коротко, послушать или пропустить.
4. Продолжайте мини-раунд, меняйте тему/глубину или завершайте игру.

Карточки не повторяются в одной игре, включая пропущенные. Новая игра делает все вопросы доступными. При возвращении предлагается продолжить незавершённую игру.

Для первого открытия нужен интернет. Готовность автономной версии можно посмотреть в разделе «Как играть»; после успешной подготовки игру можно открывать по прежнему адресу без сети. Установка через меню Chrome необязательна. Сохраняется только ход игры на этом устройстве: очистка данных сайта удалит сохранение и может удалить автономные ресурсы.

## Разработка

Проверенная среда: Node.js 26.13.1 LTS, npm 11.20.0. Vite 8.3.8, TypeScript 7.0.2, Vitest 5.1.1, Playwright 1.65.1. Выбранная LTS-ветка 26 записана в .nvmrc; она соответствует требованию пользователя «LTS не ниже 22» и engines используемых инструментов. Повторная установка Node.js не нужна, если существующая среда совместима.

Команды из корня репозитория:

```sh
npm ci
npm run dev
npm run typecheck
npm run test -- --run
npm run build
npx --no-install playwright install chromium
npm run test:e2e
npm run preview
```

В Windows папка выбранного Node.js должна присутствовать в PATH. Playwright использует отдельный локальный порт 48971. Его webServer запускается автоматически; двухверсийный тест использует 48972.

Сборка сначала сверяет все 60 карточек с исходным Excel, затем проверяет типы и генерирует полный автономный выпуск в dist. XLSX-парсер используется только в инструментах разработки; исходный Excel и документы не входят в браузерную сборку.

## Структура

- src/content — точная колода; sources — действующий Excel и SHA-256.
- src/domain — чистые переходы, выбор и валидация игры.
- src/storage — IndexedDB и атомарная запись снимка/привязки к выпуску.
- src/main.ts и src/ui — экраны, рулетки и управление разговором.
- src/offline — service worker, автономные ресурсы и закрепление выпуска незавершённой игры.
- tests — проверки логики, реального браузера и обновления A→B.
- docs — [ТЗ](docs/TECH_SPEC.md), [решения](docs/DECISIONS.md), [сценарии](docs/UX_FLOWS.md), [архитектура](docs/ARCHITECTURE.md), [публикация](docs/DEPLOYMENT.md), [результаты проверок](docs/IMPLEMENTATION.md).

## GitHub Pages

Основная ветка main. Workflow .github/workflows/deploy-pages.yml проверяет PR без публикации; обновление main после успешных проверок автоматически публикует dist на GitHub Pages.

Vite base, manifest и worker используют /nashi-istorii/. Для другого репозитория BASE_PATH задаётся перед сборкой, например /repository/. Worker не контролирует соседние проекты Pages; хранилище и кеш имеют собственный префикс.

Обновление не заменяет выпуск активной игры. После завершения можно применить новый выпуск. Записи ответов, облачное хранение, телеметрия и автоматическая расшифровка отсутствуют.

Автоматические браузерные проверки выполнены в Chromium с мобильным размером экрана. Проверка на реальном Android-телефоне, TalkBack и семейный пилот остаются отдельными этапами.
